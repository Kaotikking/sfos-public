## Convergence semantics

### `A`

`A = SEREIN CODE/SYSTEM CONVERGENCE PROVEN.`

A is not adaptive-AI maturity, personality maturity, or educational maturity.

`A NEVER MOVES.`

### Sequential letter rule

Each letter is an individual convergence goal.

`SELECT LETTER -> DEFINE -> CONVERGE CODE/SYSTEM STATE -> PROVE -> FREEZE -> SELECT NEXT LETTER.`

`ONE ACTIVE LETTER GOAL AT A TIME.`

A proven letter becomes a non-regression floor and is no longer the active goal.

`PROVEN LETTER -> FROZEN.`
`FROZEN LETTER -> MUST REMAIN TRUE.`

Current defined predecessor meanings remain:

* `Z` = Software Minimum
* `Y` = Domain / Seed Minimum
* `X` = Hardware Minimum
* `W` = High-Assurance Minimum
* `V` = Authority Minimum
* `U` = Evidence / Provenance Minimum
* `T` = Continuity / Recovery Minimum, including Operator anti-lockout
* `S` = Contract / Interface Minimum

`B–R = RESERVED / UNDEFINED` until explicitly selected/defined through governed succession.

## Locality / environment semantics

### `SEREIN_LOCAL`

A device/environment is SEREIN_LOCAL only when all three are true:

`SEREIN_OWNED + SEREINNET_ADMITTED + UNDER_DIRECT_SEREIN_GOVERNANCE.`

Direct governance does not mean single physical hop. Relayed Serein-owned Nodes/Frames remain SEREIN_LOCAL when their current identity/admission relationship remains valid.

`DIRECT GOVERNANCE != SINGLE PHYSICAL HOP.`

Loss of connectivity may make a SEREIN_LOCAL part `OFFLINE`; it does not erase ownership/classification.

### `PHYSICAL_LOCAL`

Inside Serein's assigned physical environment. Control is bounded and assigned; physical proximity/network membership does not transfer ownership.

`PHYSICAL_LOCAL != SEREIN_LOCAL.`
`ASSIGNED_CONTROL != OWNERSHIP.`

### `ON_PREMISES`

Physically hosted at the Operator/site, without implying SEREIN_LOCAL ownership or PHYSICAL_LOCAL control semantics.

### `NO_WAN`

No usable Internet path.

`NO_WAN != OFFLINE.`

### `ONLINE` / `OFFLINE`

Status of a named Serein part/service/domain/endpoint under its declared online criterion.

## Control semantics

### `CODE_DOMINANCE`

Serein owns the implementation/code surface of a SEREIN_LOCAL component sufficiently to inspect/configure/replace/repair/evolve it within current Blueprint/governance authority.

`CODE_DOMINANCE != SELF_AUTHORIZATION.`

### `ASSIGNED_CONTROL`

Bounded authority granted over a named external/PHYSICAL_LOCAL device/service/action surface.

## Capability semantics

`DOCUMENTED_CAPABILITY -> PHYSICAL_CAPABILITY -> VERIFIED_CAPABILITY -> ADMITTED_CAPABILITY -> ACTIVE_CAPABILITY`

No later state is inferred from an earlier state.

Bare `AVAILABLE` is not a machine state.

## Runtime mode semantics

### `FOCUS_MODE`

A bounded attention/priority mode around a declared target `N`.

`FOCUS = WHAT SEREIN CONCENTRATES ON.`

`FOCUS != AUTHORITY.`
`FOCUS != TRUTH FILTER.`
`FOCUS != OVERDRIVE.`

Canonical intent: `FOCUS_ON(N)`.

Focus may prioritize/reduce unrelated attention but may not suppress required safety, recovery, authority, or Operator-significant events.

### `OVERDRIVE`

Operator-requested temporary performance mode.

`OVERDRIVE = HOW HARD SEREIN MAY RUN.`

Normal runtime remains energy-efficient/minimum-necessary resource use.

`OVERDRIVE != BLUEPRINT MODE.`
`OVERDRIVE != CONVERGENCE STATE.`
`OVERDRIVE != AUTHORITY.`

If Overdrive cannot be sustained, Serein returns to normal/degraded performance without changing authority or identity.

### `TURBO`

Bounded acceleration/resource function invoked by Overdrive.

`TURBO != MODE.`
`TURBO != SAFETY BYPASS.`

Focus and Overdrive may compose:

`FOCUS_ON(N) + OVERDRIVE -> PRIORITIZE N + APPLY TEMPORARY ADMITTED PERFORMANCE.`

## Education semantics

### `TEACHING_MODE`

Instructional delivery state. Personality state is set/fixed for the declared teaching session/profile and clears/rebinds on end/interruption/operator/profile change.

### `LEARNING_MODE`

Serein acquisition/understanding state. Personality may be fluid within Personality Blueprint bounds while facts/provenance/admission remain unchanged.

## Output semantics

### `CANONICAL_OUTPUT`

Source-domain factual/result representation with required context, uncertainty, provenance, and safety but without Personality presentation adaptation.

### `PERSONALITY_ADAPTED_OUTPUT`

Same underlying truth/constraints rendered through admitted Personality/Operator presentation adaptation.

`PERSONALITY_BYPASS != GOVERNANCE_BYPASS.`

## High-risk generic words

### `MODE`

Bounded runtime posture; exact machine contracts use a namespaced mode. Mode never creates authority.

### `STATE`

Current value of one named state-machine dimension for an exact target; namespace and freshness required where material.

### `ENVIRONMENT`

Named execution/deployment context with explicit identity, boundary, config/source identity, and locality/control class.

### `OWNER`

Single accountable Serein domain/role for the named capability/contract/state.

`CONTRIBUTOR != OWNER.`

### `CONNECTED`

A declared transport/session/path connection exists under the named criterion.

`CONNECTED != IDENTIFIED != AUTHENTICATED != TRUSTED != AUTHORIZED.`

### `HEALTHY`

Named target satisfies a declared health criterion with adequate freshness.

`HEALTHY != CORRECT.`
`HEALTHY != AUTHORIZED.`
`HEALTHY != PROVEN.`

### `CURRENT`

Supported by sufficient freshness/version evidence for the declared purpose.

### `ACTIVE`

Named actor/service/task/capability is currently operating/executing with the required fresh evidence. Namespace when class matters: `TASK_ACTIVE`, `SERVICE_ACTIVE`, `CAPABILITY_ACTIVE`.

### `TRUSTED`

Named identity/object/relationship is admitted into a specific scoped, revocable trust relationship under current policy.

`TRUSTED != AUTHORIZED FOR ALL ACTIONS.`

### `SECURE`

Bare SECURE is prohibited as a controlling pass/state. Security claims must name exact property/scope/threat model/evidence.

### `SAFE`

Exact target/state satisfies its declared safety invariants/prohibited outcomes for the named scope.

`SAFE != NORMAL.`
`SAFE != HEALTHY.`

### `COMPLETE`

Bounded task/deliverable outputs are finished.

`COMPLETE != VERIFIED != ACCEPTED != ADMITTED != LIVE.`

### `READY`

Bare READY is prohibited as a controlling state. Use an exact namespaced readiness state.

### `CANONICAL`

Current admitted governing reference for an exact scope/version.

`CANONICAL != IMPLEMENTED.`
`CANONICAL != LIVE.`

## Alpha phase / migration semantics

### `ALPHA`

Project lifecycle phase. Alpha ends at the Operator-declared final Alpha code-convergence/public-archive transition.

### `PUBLIC_ARCHIVE`

Frozen historical public release of completed Alpha material appropriate for publication.

`PUBLIC_ARCHIVE != ACTIVE_AUTHORITY.`

### `PROJECT_IDENTITY_MIGRATION`

Governed move of active project tooling/accounts/providers while preserving Blueprint/Seed/Dictionary/domain/provenance identity.

`PROVIDER CHANGE != BLUEPRINT CHANGE.`
`ACCOUNT CHANGE != AUTHORITY CHANGE.`
`TOOLING CHANGE != DOMAIN CHANGE.`

## Legal/provenance semantics

`IF CODE ENTERS SEREIN -> ORIGIN + LICENSE STATUS ENTERS WITH IT.`

`UNKNOWN LEGAL ORIGIN -> NO ADMISSION.`

`LEGAL_REVIEW_REQUIRED` = unresolved license/copyright compatibility or obligation requiring qualified review before public-release admission.

`PUBLICATION_PASS REQUIRES LICENSE_PROVENANCE_PASS.`

## Anti-dual-meaning rule

If a term could map to more than one canonical meaning and the distinction can change behavior:

`AMBIGUOUS TERM/OPERAND -> UNKNOWN / NO ADVANCE.`

Legacy wording is mapped to v3 before implementation/proof.
